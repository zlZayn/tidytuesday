# 决策：把视觉身份说明从报告里搬走（2026-10-28）

状态：生效

## 问题

[视觉身份策略](2026-09-20-visual-identity-policy.md) 要求每周回报「主色 hex + 图表家族 + 版式签名」以防趋同，各周把这套回报写成了报告开头的引用块。
这违反同一份策略的「产物洁净度」条款和根 [AGENTS.md](../../AGENTS.md)「内部笔记不得进 HTML」：读者打开报告，第一段读到的却是 hex 色值、`不写入共享 theme`、字号阶梯 `16 / 13 / 11 / 9.5 / 8.5 / 7.5 pt`。
内容还会漂：这些块各写「六周互不相同」「八周互不相同」「九周互不相同」「十周互不相同」，实际已是十三周，同一事实有四个互相矛盾的版本。

## 决策

- 十三周的身份登记集中到 [视觉身份登记](2026-10-28-visual-identities-registry.md)，页面不再承载。
- 2026-09-22 ~ 2026-10-27 五周的引用块随首次交付就不写；2026-08-25 / 09-01 / 09-08 / 09-15 / 09-29 五周删除该块并重渲染。
- 已发布周重渲染会把「发布于」写成构建当天，因此这几周的 `date:` 就地冻结为其原发布日期（`2026-08-18` / `08-25` / `09-01` / `09-15` 为 `2026-09-20`，`09-29` 为 `2026-10-01`），正文其他内容逐字不变。
- 2026-08-11 的同一段说明早已是 HTML 注释，无需改动。
- 附录表里的设计说明同批清掉（2026-10-29 追加）：2026-08-18 的「本周视觉设计」表 6 行改写成一句读者语、只留类别色与考试类型的对应；2026-08-25 的「视觉身份」行改为「配色与含义」（保留颜色→系列映射、去掉 hex 与版式术语）、删掉「字体与导出」行；2026-09-01 删掉「第 4 色的依据」（CIEDE2000 选色推理）整行、「为什么地图与时间轴在同一张图上」去掉 patchwork 措辞、「投影与底图」改为不露代码的写法。判断口径：只保留读者据此读图需要知道的东西（颜色与系列的对应、面板之间怎么对照），维护者才知道的（hex、dpi、字号阶梯、选色算法、CIEDE2000）一律退出页面。

## 替代方案（强制）

- 只清五周新报告：范围最小、零风险，但站点会长期处于「8 周有、5 周无」，读者看到的是两套页面开头。
- 十三周全清但不动 `date:`：每份旧报告的「发布于」会被改写成 2026-10-28，八月的周显示十月发布，是把技术动作的副作用写进读者可见的事实。
- 只改 HTML 里的那段文字、不重渲染：下一个人重渲染就回来了，且产物与 qmd 脱钩，违反「产物由 qmd 渲染得到」。
- 把身份登记留在页面里当作「设计说明」给读者看：与策略的洁净度条款直接冲突，且读者要的是数据故事，不是字号阶梯。

## 影响

- 十三周页面开头统一为「H1 → 首屏 KPI → 正文」，不再有维护者语气。
- 已发布周 qmd 的 `date:` 由 `today` 变为固定日期：该字段此后不再随构建漂移，重渲染其余内容仍会改变产物字节（字体是否内嵌取决于渲染时能否取到 Google Fonts，见根 AGENTS.md 活跃坑）。
- 新增周仍按三项回报身份，但写进登记表与 PR 说明，不写进报告。
