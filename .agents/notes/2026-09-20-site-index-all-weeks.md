# 决策：入口页收录全部周（2026-09-20）

已实施：`code/update_site.R` 由「只认 02」改为「02 优先、回退 01」，侧边栏按目录名降序（新 → 旧）列出全部周。

## 问题
- 原规则只收录渲染出 `output/02_exploratory_visualization.html` 的周：只有数据检查的周在站点上完全不可见，维护者看不出「这周做过但没有可视化」。
- 维护者要求「展示全部周，左侧 tab 切换，从上到下从新到旧」。

## 决策
- 收录优先级：`02_exploratory_visualization.html` → `01_data_check.html`；两者都没有的周不进列表。
- 回退条目在侧边栏带「数据检查」标记，避免访客把数据检查误当可视化。
- 排序与默认不变：目录名降序（新 → 旧），最新周为 iframe 默认内容。
- 站点入口页由 CI 每次 push 重跑脚本生成，本地手改仍会被覆盖。

## 替代方案
- 保持只认 02（原状）：站点永远只有可视化周，维护者无法从站点看出数据检查周。
- 每周同时列两个条目（可视化 + 数据检查）：信息全，但侧边栏条目翻倍，切换成本高。
- 回退到 `01_data_check.html` 但不加标记：访客会把质量检查报告当可视化看，属于信息误导。
- 手写 index.html 周清单：与既有决策「入口页由脚本生成」冲突，清单会漂。

## 影响
- 契约变更：`code/update_site.R` 的收录规则、[weeks/README.md](../../weeks/README.md) 硬编码约定段、[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) 的约束与防错清单、根 [AGENTS.md](../../AGENTS.md) 活跃坑必须同一次改动内同步；既有决策记录的过时断言也要就地更新（本轮已改 visual-identity-policy 与 docs-network-and-week-order 两处）。
- 站点在只有 01 的周不再「空白」，但默认展示的是数据检查——需要视觉区分（已加标记）。
- 新增周只要渲染出任一产物并 push，就会自动出现在列表顶部。
